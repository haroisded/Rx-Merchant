SET-B1 - First-run wizard and seed
  assets/country_info.json: 250 countries from Frappe's
  frappe/geo/country_info.json (MIT), trimmed to currency, symbol, fraction,
  fraction units, smallest fraction, date and number format. Number formats
  outside the six the app supports were mapped to the nearest one.
  Wizard: Language, Region (Country and Currency pickers with a format
  preview; the device's country is preselected), Store (name; abbreviation
  suggested from the initials), Done ("Open Cash Register", "Add your first
  item"). Phone: one step per screen. Tablet: centred 560dp card.
  completeSetup() writes, in one transaction: the Currency, warehouse tree
  (All Warehouses > Stores), item groups, 13 UoMs, Standard Selling, three
  Modes of Payment, the "Main Counter" POS Profile with Cash, the seven
  naming series, a default Letter Head, Stock Settings defaults, Selling
  Settings, Store Profile and System Settings, then setup_complete = 1.
  Files: lib/features/setup/data/{country_info,seed}.dart,
  lib/features/setup/ui/wizard_screen.dart, lib/router.dart (?next= landing).

SET-B2 - Store Profile, System Settings, Global Defaults; formats app-wide
  One settings form, SinglesForm, drives all four settings pages from a list
  of fields. System Settings shows a live preview (today and 1234567.891).
  Default Currency and Currency Precision lock once any document is
  submitted, with a lock icon and the reason.
  Formats (number, money, date, time) come from one provider, so changing a
  setting changes every screen. parseNumber reads typed numbers in the
  chosen Number Format.
  Files: lib/core/numbers/{format,formats}.dart, lib/core/db/providers.dart,
  lib/features/setup/ui/settings_pages.dart,
  lib/features/setup/data/setup_queries.dart (anySubmittedDocument).

SET-B3 - Currency and Price List
  The store currency's form with a live amount preview. Price List list and
  form; the last enabled list cannot be disabled or deleted.
  File: lib/features/setup/ui/simple_masters.dart.

SET-B4 - Naming Series
  Pick a document, reorder or add series (the first is the default), see the
  next name. Update Series refuses a number below one already used by any
  document or item name.
  File: lib/features/setup/ui/naming_series_page.dart.

SET-B5 - Mode of Payment
  List and form (Name, Type, Enabled). A mode in use cannot be deleted: the
  database's foreign keys refuse it and the app says "disable it instead".

SET-B6 - Tax, Sales Taxes and Charges Template, Item Tax Template
  Pure logic in lib/features/setup/logic/tax_template.dart: the SET-R9 row
  checks, the "Try it" calculation, the SET-R12 item rate override, and
  renumbering of Reference Row # when a row is deleted. The template form has
  the row editor (bottom sheet on phones, side sheet on tablets) and the
  "Try it" panel. Making a template the default clears the old default.
  File: lib/features/setup/ui/tax_template_pages.dart.

SET-B7 - POS Profile and Selling Settings
  The form in ERPNext's section order: warehouse (non-group only), payment
  methods (Default, Allow in Returns), the eight switches and Action on New
  Invoice, item groups, print settings, price list, taxes, Apply Discount On.
  Save refuses: a group warehouse, not exactly one default payment, disabled
  choices, an edit while the profile's session is open, and anything that
  would leave the enabled profiles without exactly one default.
  File: lib/features/setup/ui/pos_profile_page.dart.

SET-B8 - Data Import and Data Export
  Item, Item Price and Item Barcode, Insert or Update. Download Template,
  Choose File (CSV), map unknown headers by hand, then every row is checked
  before anything is written: missing mandatory value, duplicate name,
  record not found, unknown link, bad number / date / value. Problems are
  listed by row and column; nothing is imported until all are fixed. The
  import runs in one transaction and lists what it created or updated.
  Export writes the same columns, so an export can be edited and imported
  back as an update.
  Files: lib/features/setup/logic/data_import.dart,
  lib/features/setup/data/data_import_db.dart,
  lib/features/setup/ui/data_pages.dart.

SET-B9 - Backup and Restore
  Back up now: VACUUM INTO {abbr}-backup-{YYYYMMDD-HHMMSS}.sqlite in the
  app's backup folder; only the newest Number of Backups files are kept.
  Export saves a backup anywhere through Android's save dialog. Restore picks
  a file, checks it is a SQLite file with `singles` and a schema version no
  newer than the app's, refuses while a POS session is open, backs up the
  current data, replaces the file and reopens the database.
  File: lib/features/setup/data/backup.dart.

Shared pieces
  form_kit.dart: problems dialog, refusal messages, confirm dialog, form page
  with Save/Delete, two-column field grid from 600dp, master list with
  search, Add and an empty state. refusal.dart: refusal codes the UI turns
  into translated text; UNIQUE and FOREIGN KEY failures become "name already
  exists" and "used elsewhere, disable instead".
  setup_screen.dart: the Setup workspace and the page for each route.
  About 200 new messages in lib/l10n/app_en.arb.

6.1 Problems found and fixed (Ponytail: smallest fix at the root)
  Spec reviewer:
   1. Currency form saved Smallest Currency Fraction Value as 1 instead of
      0.01 in stores using "#.###,##" (25 countries). Fixed: the field shows
      the value in the Number Format, so it reads back unchanged.
   2. In "#.###" stores, typing 7.5 saved 75. Fixed in parseNumber: a group
      must have the format's size, so 7.5 is refused, and a format without
      decimals accepts the other mark (7,5) as the decimal point. 1 new test.
   3. Deleting a tax row left later Reference Row # pointing at the wrong
      row. Fixed with removeTaxRow(), which renumbers; 1 new test.
   4. Backups page offered 1-20 while System Settings allows more. Fixed.
   5. Errors other than refusals were not shown: the wizard buttons could
      stay disabled, and a failed restore could leave the database closed.
      Fixed: attempt() shows any error; restore always reopens the database.
   6. A blank Abbreviation was kept, so backups were named "-backup-...".
      Fixed in StoreProfile.abbr (falls back to initials); 1 new assertion.
   7. ".FY." was accepted in a naming series. Fixed: refused with a message.
   8. The Update Series test did not check the next name. Added.
  Standards reviewer:
   9. modified_at was not set on three updates (Item Price update, cleared
      default template, cleared default profile). Fixed.
  10. Screens queried the database directly (POS Profile and Item Tax
      Template loading, Currency insert on Store Profile). Moved into query
      methods; the Currency mapping now lives once on CountryInfo, used by
      the wizard seed and Store Profile.
  11. countryInfoProvider sat in data/. Moved to ui/.
  12. Raw error text was shown untranslated. Now goes through a message.

6.2 Reported and left as they are, on purpose
  - Setup forms use DropdownMenu for links; 00-overview 7.1 names a
    SearchAnchor with "Create new". The lists are short, so a dropdown shows
    every choice at once. LinkField is used where lists are long (country,
    currency). Change if you want "Create new" from inside a form.
  - Stored option values (charge types, Mode of Payment types, Rounding
    Method, record type names) are shown as stored, in English. They are
    ERPNext's own words; translate them when a second language ships.
  - FieldGrid switches to two columns on the pane width, not the window
    width, so a form inside the tablet's right pane lays out correctly.
  - The import log lists the imported records, not the Item Prices created
    from Standard Selling Rate or the barcode rows.
  - Data Import also applies three stock rules (Item Price from Standard
    Selling Rate STK-R5, EAN check digit STK-R8, no overlapping price
    validity STK-R10). Not in SET-R16's list; kept so imports cannot write
    data the stock plan forbids.
  - Judgement-call smells: three similar master pages, page slugs listed in
    two places in setup_screen.dart, short names such as Col. Not changed.

12. FOLLOW-UP: RESTORE FROM THE WIZARD (asked for after the report)
-------------------------------------------------------------------

Why
  Setup, and with it the Backups page, is behind the wizard gate (SET-R1).
  A new device had to finish the wizard with throwaway answers before it
  could restore, and that detour left a junk safety backup of the
  throwaway store. Restoring onto a new device is the main use of backups.

What changed
  - Wizard, step 1: "Moving from another device? Restore a backup instead
    of setting up again." and a "Restore from backup" button. It picks the
    file, restores it and reopens the database; with setup complete in the
    restored data the router leaves the wizard by itself. No confirm
    dialog: a fresh install has nothing to lose.
  - restoreDatabase (data/backup.dart): the safety backup is taken only
    when setup was finished; a never-set-up store holds nothing to keep.
    One guard in the shared function covers both callers. Optional
    target and backupDir parameters let the test run off-device.
  - pickBackupCopy() and restoreAndReopen() (ui/data_pages.dart): the
    Backups page's pick-copy-restore-reopen steps, now shared by the
    Backups page and the wizard.
  - Two messages added to app_en.arb (227 in all).
  - Tests: restore onto a fresh install takes no safety backup and the
    restored file holds setup_complete = 1; onto a set-up store it takes
    one. The fresh-install wizard test checks the button is shown.
    140 of 140 pass.
