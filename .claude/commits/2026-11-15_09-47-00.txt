3. WHAT WAS BUILT (M0, STEPS 1 TO 7)
------------------------------------

Step 1 - Project setup
  Added the packages of plan section 4 except thermal printing: drift,
  drift_flutter, flutter_riverpod, go_router, mobile_scanner, pdf, printing,
  fl_chart, file_picker, share_plus, path_provider, image_picker, intl, csv,
  flutter_localizations; dev: drift_dev, build_runner.
  Added android/app/src/release/AndroidManifest.xml, which removes the
  INTERNET permission from release builds even when a plugin declares it.

Step 2 - Database schema version 1
  48 tables and 14 indexes, written as SQL in four .drift files, one per
  feature (setup 14, stock 22, pos 8, invoices 3), plus the batch table in
  Dart. created_at and modified_at on the 24 master and document tables.
  Foreign keys are switched on at every open.

Step 3 - Settings access
  readSingle, watchSingle, writeSingle on the singles table, and six typed
  classes with defaults: StoreProfile, SystemSettings, GlobalDefaults,
  SellingSettings, StockSettings, PrintSettings (51 keys).

Step 4 - Rounding and formatting
  flt(value, precision, method): Banker's and Commercial rounding, correct
  on binary float midpoints (2.345, 1.005) and on negative amounts.
  formatNumber for the six number formats, formatCurrency, formatDate,
  formatTime, toStorage.

Step 5 - Naming series
  parseSeries resolves a pattern such as ACC-SINV-.YYYY.- against the
  posting date. nextName takes the next number in its own transaction, so a
  failed submit does not use a number up.

Step 6 - Theme, localisation, shell, router, gate
  Material 3 light and dark themes from one seed. gen-l10n with 21 English
  messages. go_router with a stateful shell of five destinations. Bottom
  NavigationBar under 600dp, NavigationRail from 600dp, rail with labels
  from 840dp. The gate: only the wizard is reachable until setup_complete
  is set.

Step 7 - Shared widgets
  WindowSize, AppSpacing, ListDetailPane, LinkField, ChildTable and
  showRowEditor (bottom sheet on phones, side sheet on tablets), StatusChip,
  ReportTable and toCsv.

7. DECISIONS MADE ON YOUR BEHALF
--------------------------------

Each with the reason, and what it costs if it was the wrong call.

  1. No commits, no branch, no worktree. You commit.
     Cost: no per-task history.
  2. kotlin.incremental=false in android/gradle.properties. The release
     build failed without it: project on B:, pub cache on C:.
     Cost: slower Kotlin recompiles.
  3. series.current is quoted in setup.drift (CURRENT is an SQL keyword).
     Row class renamed SeriesRow (drift's default was "Sery"). Cost: none.
  4. The batch table is declared in Dart
     (lib/features/stock/data/batch_table.dart), not in stock.drift. Its
     generated getter clashed with drift's own batch() method. The SQL name
     and columns are unchanged.
     Cost: one table in a different file; one build_runner warning.
  5. setup.drift and stock.drift import each other; per-feature files kept.
     Cost: none found.
  6. SystemSettings.roundingMethod returns the stored text;
     RoundingMethod.fromSetting converts it.
     Cost: one conversion at each use.
  7. Date and time formatters are pinned to the en_US locale, so stored
     date text stays ASCII.
     Cost: displayed dates never use native digits.
  8. Added a /loading route, so a set-up store does not flash the wizard at
     launch. Cost: one route.
  9. Added AppSpacing (spacing scale) and a placeholder wizard screen with a
     temporary "Finish setup" button. M1 replaces the wizard.
     Cost: two small files.
 10. LinkField has an errorText parameter and a clear button on optional
     fields. StatusChip translates known statuses.
     Cost: two small parameters.
 11. Generated localisation files are excluded from analysis; they use
     delegates deprecated in Flutter 3.47.
     Cost: real problems in generated code would go unreported.
 12. cupertino_icons kept. Without it every build warned about a missing
     icon font. Cost: one small dependency.
 13. "generate: true" and providers.dart were added in step 6 instead of
     steps 1 and 3, where their first use is. Cost: none.
 14. Nav label "Register"; launcher label "Rx Merchant" (this follow-up).
     Cost: change one message or one attribute.
 15. Fallow replaced by Dart tools for the review (this follow-up).
     Cost: the review is not the one CLAUDE names.

8. KNOWN PROBLEMS AND OPEN ITEMS
--------------------------------

  1. Emulator rendering fault. In hardware GPU mode on this machine, the
     first app launch after the emulator boots, or after the display density
     changes, can draw the first screen after the wizard with text missing
     (app-bar title, part of the body text; earlier, on the tablet, rail
     icons and labels). It clears on the next repaint.
     Measured, phone emulator, same release APK:
       hardware GPU   2 of 2 trigger launches showed it; 6 warm relaunches
                      were clean
       software GL    0 of 3 trigger launches; 0 of 6 overall
     So it follows the emulator's GPU path. The samples are small and the
     cause inside the emulator is not known. It has not been checked on a
     real device. In the earlier report I called this a one-off; it is
     reproducible.
     Workaround for screen checks: start the emulator with
     -gpu swiftshader_indirect.
  2. No real device was used for any check.
  3. modified_at is never updated. Each milestone that adds an update must
     set it.
  4. build_runner prints one warning about the batch table's foreign key.
     The constraint is correct; the schema test passes.
  5. The release APK is signed with the debug key (Flutter template
     default). Fine for installing; it cannot be published.
  6. The wizard is a placeholder. "Finish setup" collects nothing.
  7. ACCESS_NETWORK_STATE is in the release manifest, added by a plugin.
     Harmless without INTERNET.

11. BEFORE YOU COMMIT
---------------------

  - CLAUDE.md is now CLAUDE.txt. Claude Code loads CLAUDE.md automatically
    at the start of a session; it does not load CLAUDE.txt. Rename it back
    if you want the rules applied without pointing at the file.
  - .gitignore has the line ".claude\erpnext-planner" with a backslash. Git
    does not treat a backslash as a path separator, so the line matches
    nothing and that folder is still tracked. Use a forward slash if you
    meant to ignore it. Note that the system documentation lives there.
  - graphify-out/cache/ can be rebuilt with "graphify update ." at any time.
    Add it to .gitignore if you do not want 37 cache files in the repository.
  - The two generated code sets (app_database.g.dart, app_localizations*.dart)
    are not ignored and will be committed. That keeps a fresh clone
    buildable without running build_runner first.
